\subsection*{Data extraction and standardization}

Source records were per-patient multi-sheet workbooks (\kmuh) or a shared master workbook plus case-presentation slide decks (\tvgh and \tsgh). Workbooks were parsed deterministically into raw sections. Slide decks were parsed for text and embedded images, with an optional vision-model pass for image-only tables (\todo{model and version used for the historical runs}), and linked to registry cases by patient, date and file cues. \subsection*{Overview of \toolname}
% run_full_pipeline.py (build_plan), docs/WORKFLOW.md, docs/FULL_PIPELINE.md, Supplementary Table 5
\toolname processes one patient at a time through five stages in a fixed order (Fig.~\ref{fig:overview}): modality agents read the standardized sections and a deterministic summary joins their outputs; a deterministic scorer grades every organism on the \mngs report and picks the causative candidates; a language-model safety review flags unpicked organisms for further evidence gathering without altering the picks; four evidence modules (literature, patient case-fit, sequencing strength and direct hospital evidence, plus a reported colonization gate) are computed for every carried candidate, and the final rule \rfive fixes the delivered list; and a rationale is generated for the frozen selection, audited and exported. Language models are used only for extraction and judging, each with a fixed prompt and JSON output schema (Supplementary Table~5); every selection decision is made by explicit rules whose thresholds are held in versioned configuration files. Each stage writes its outputs together with the rule identifiers that fired and the SHA-256 hashes of its inputs, so that any decision can be traced to the finding that determined it. The model identifiers and sampling settings given below are the repository's configuration bindings at the time of writing (\todo{confirm each against the run manifests of the reported runs, and give the dates on which each service was accessed}).

\subsection*{Modality agents and clinical summary}
% upstream/tools/analyze_llm_agent.py (DEFAULT_MODEL gpt-5:27; responses.create temperature=1:288-292), upstream/agents/prompts/*, upstream/tools/build_deterministic_summary.py (summary_deterministic_from_agents_v4_evidence_preservation), deterministic_mngs_max_scorer.py (host_context:761-781)
Each standardized section is read by a dedicated language-model agent (OpenAI \texttt{gpt-5}, temperature 1) with a fixed prompt and JSON output schema: a blood-count, laboratory and host agent that also assigns a host-vulnerability tier (V0--V3) and an opportunistic-coverage level (O0--O2) from immunosuppression, malignancy, corticosteroid exposure, renal failure and related conditions; a culture agent; a \filmarray and galactomannan agent; a molecular-microbiology agent; an imaging agent; and an \mngs-to-specimen agent that assigns each reported organism to a specimen and body site with a likelihood class (high, medium or low-colonizer). Each agent sees only its own section; the agents do not communicate, and none sees the reference labels. A deterministic summarizer (rule version v4) combines the agent outputs into per-organism support by modality (support, not support or unknown), specimen alignment (aligned; sterile or systemic; non-aligned) and a host context; a language-model summarizer used in earlier versions was retired. The host context sets a host-expansion flag when the vulnerability tier is V2--V3 or the opportunistic coverage is O1--O2; the flag relaxes the picking of level-3 organisms (below) but never promotes an organism by itself.

\subsection*{Features of \mngs organisms}
% upstream/tools/rank_mngs_candidate_microbes.py (CODE_SCORES:14-20, RANK_RULES:22-28, scoring:105-155), upstream/tools/mngs_common.py (read tiers:303-314; canonical names), deterministic_mngs_max_scorer.py (dominance_by_record:1539-1562)
Each organism on the \mngs report is described by five features (Supplementary Table~1). A control-subtracted priority from 1 (best) to 5 is assigned from the control codes, evaluated in order: 1 when NTC is 00 and RK is 00; 2 when RK is 8 and NTC is 00; 3 when RK is 00; 4 when RK is 8; and 5 when only NTC is 00. A code score (1.0, 0.85, 0.65, 0.45 and 0.30 for priorities 1--5) is combined with the percentile rank of $\log_{10}(\text{reads}+1)$ among all organisms in the same run as $0.6 \times \text{code score} + 0.4 \times \text{percentile}$, and the result is labelled high ($\ge 0.70$), medium ($\ge 0.45$) or low. Read burden is tiered at decade thresholds: R0, 1--9 reads; R1, $\ge 10$; R2, $\ge 100$; R3, $\ge 1{,}000$; R4, $\ge 10{,}000$. Dominance is computed within each specimen record from the ratio of the top organism's reads to the runner-up's: D3 when $\ge 10$, D2 when $\ge 3$, D1 otherwise, and D0 for every organism that is not the top. When an organism appears in several specimen records of one patient, the record with the best priority and then the most reads is kept. Organism names are normalized through a canonical dictionary that merges synonyms (for example, CMV and human cytomegalovirus) but never merges species.

\subsection*{Deterministic scoring and picking}
% upstream/tools/deterministic_mngs_max_scorer.py: m1_strong:1565, m2_moderate:1581, m3_protected:1732, m4_weak:1754, set_candidate_level_from_tier:1813, level3_pickable:2784, pickable:2821, build_best_available:2892, guardrail constants:19-45; mngs_common.py (protected and background lists:33-60)
The scorer assigns each organism an \mngs signal tier from M1 (strong) to M5 (background) on the basis of its priority, read tier, percentile, dominance and likelihood class; the clauses are evaluated in order and the first satisfied tier applies (Supplementary Table~2). M1 requires priority~1--2 with R3--R4 reads, priority~1--2 with percentile $\ge 0.85$, or D3 dominance with at least R2 reads at priority $\le 3$. M2 requires priority~1--2 with R2 reads and percentile $\ge 0.75$; D2--D3 dominance with at least R2 reads at priority $\le 3$; same-organism support from a hospital test with at least R1 reads at priority $\le 3$; a protected pathogen (other than a reactivation virus or mould) with at least R1 reads, priority $\le 3$ and a non-low label; R3--R4 reads at priority $\le 4$ with a non-low label; \textit{Pneumocystis jirovecii} with R1--R2 reads at priority $\le 3$; or a Mucorales organism at priority~1 with percentile $\ge 0.60$. M3 covers protected pathogens that meet a retention condition and, otherwise, priority~1--2 with R0--R2 reads, priority $\le 3$ with percentile $\ge 0.60$ above trace reads, or priority~4 with R4 reads. M4 applies to priority~4--5, a low likelihood class, R0--R1 reads or a non-aligned specimen; M5 marks organisms on the background list. The protected-pathogen list comprises \textit{P.~jirovecii}, cytomegalovirus, herpes simplex virus types 1 and 2, \textit{Toxoplasma gondii}, \textit{Nocardia}, \textit{Legionella}, \textit{Mycobacterium tuberculosis}, \textit{M.~avium}, \textit{M.~kansasii}, \textit{M.~abscessus}, \textit{Aspergillus}, the Mucorales, \textit{Histoplasma} and \textit{Cryptococcus}; reactivation herpesviruses and moulds have dedicated M2--M3 clauses that require non-host support or dominance.

Tiers map to causative levels 1--5. M1 becomes level~1 when the specimen is aligned or sterile and the organism is dominant or carries R3--R4 reads, and level~2 otherwise; M2 becomes level~2 when aligned and level~3 otherwise; M3 is level~3; M4 is level~3 only under host expansion when the organism remains plausible (not a reactivation virus, colonizer or non-aligned finding, and with non-host support, protected status, or priority $\le 3$ with R1 reads and a high or medium label), and level~4 otherwise; M5 is level~5. Before picking, 33 pre-specified guardrails (identifiers \texttt{R-S4-*}; Supplementary Table~3) demote organisms to level~4 or bar them from picking regardless of tier. They cover generic unidentified hospital labels; respiratory \textit{Candida} without same-species invasive evidence, or supported only by non-invasive hospital tests; oral and aspiration flora, of which one representative is retained at level~3 when a compatible aspiration pattern exists; water-borne environmental Gram-negative bacteria without dominance or support; skin flora and coagulase-negative staphylococci; low-actionability viruses (Epstein--Barr virus, human herpesviruses 6 and 7) and non-core respiratory viruses; weak mould signals with host-only support; \mngs-only R0--R1 non-protected organisms; common hospital organisms with low, non-dominant reads; non-pulmonary culture context; retention of one organism per taxonomic group; and a rule that prevents trace-read protected pathogens from being picked without support.

Organisms at level~1--2 are picked. Level-3 organisms are picked only with a protected or supported rationale: protected-pathogen status; an oral-flora or respiratory-commensal representative rule; a compatible typical-pneumonia context; direct support from culture, \filmarray, galactomannan or molecular testing; or, under host expansion, priority $\le 2$ with at least R2 reads or D2--D3 dominance. \textit{Candida} and generic yeasts are never picked at level~3 without invasive support. When nothing is pickable, the best level-4 organisms that pass the exclusion rules are reported as ``best available'' and flagged as such. Picked organisms are ordered by level, then signal tier, then reads, and the first level~1--2 organism is labelled primary. Every organism, picked or not, is written out with its level, the rule identifiers that fired and an exclusion reason code. The reported decisions were produced with scorer version v19 (\texttt{mngs\_deterministic\_level\_only\_v19\_low\_specificity\_taxonomy}); the current version \vtwenty (\texttt{v20\_central\_taxonomy\_profile}) centralizes the taxonomy profiles and reproduces the picked set in all \todo{55} patients, with candidate-level differences in \todo{15} and pick-order differences in \todo{5} (Supplementary Note~4).

\subsection*{Safety review of unpicked organisms}
% upstream/tools/build_missed_candidate_review_queue.py, review_missed_mngs_candidates.py (DEFAULT_MODEL gpt-5:22; prompt:274-360), merge_deterministic_max_with_missed_review.py
Organisms that were not picked are queued for review by a language model (OpenAI \texttt{gpt-5}) that receives the deterministic output, the hospital-side summary and the \mngs-to-specimen classes. The prompt (Supplementary Note~1) instructs the model that it may not replace or reorder the picked list, that immunocompromise and protected status are not by themselves grounds for upgrade, and it restates the colonization, reactivation, oral-flora, environmental and \textit{Candida} rules with explicit read, rank and dominance conditions. The model assigns each organism to one of four tiers: high priority and context needed, which are carried into the evidence stage, and low specificity and omitted with reason, which are retained for audit only. The merge step appends the carried organisms to the deterministic output without altering it and records the tier of every organism. In the replay of the \todo{55} reported patients, picked sets and tier membership were identical in all patients.

\subsection*{Literature evidence (module A)}
% RAG_re/rag_re/pubmed.py (build_query:40-46), engine.py, judge.py, rules.py (module_a_from_judgments:136-218), config/default.json (publication_cutoff 2026-06-30; min_support 3; min_judgeable_articles 5), config/formal_merge_full_a.json, prompts/article_support_v1.txt
For each carried candidate, and for each upstream pick (literature on picks was enabled in the reported runs), PubMed was queried through the NCBI E-utilities with the organism name in the title or abstract, combined with a disjunction of lower respiratory tract infection site terms and restricted to publications up to 30 June 2026; at most ten articles were retrieved, and every query and response was cached with its hash. Each title and abstract was judged by a language model (OpenAI \texttt{gpt-5.6-luna}, reasoning effort low, at most 1,200 output tokens, prompt version \texttt{article\_support\_v1}) for whether it provides human clinical evidence that the exact species causes infection at the target site. The judge returns a verdict (support, against, irrelevant or unclear), the organism scope (exact species, genus only or other), human-clinical and target-site indicators, and an evidence span that must be a contiguous excerpt of at most 20 words from the supplied text. A support verdict counts only when the scope is the exact species, the evidence is human and clinical, the site matches and the span is valid. Module A is positive when at least three valid supports exist among at least five judgeable articles; with fewer than five judgeable articles, or when retrieval fails, it abstains rather than voting negative. A literature-off branch exists for cost control and was not used for any reported number.

\subsection*{Patient case-fit (module A1)}
% RAG_re_casefit/rag_re_casefit/{rules.py (derive_article_verdict:40-120), batch.py, case_card.py, judge.py}, config/default.json, prompts/article_casefit_v1.txt
Each retrieved article is re-judged against a case card built from the patient's standardized record. The case card contains the specimen and site, the clinical syndrome, host factors, phenotype (imaging and laboratory patterns) and timing; it deliberately excludes the reference labels, the upstream picks, read counts, culture and PCR results and any review rationale, so that the judgement concerns the fit between the published patients and this patient rather than the strength of this patient's evidence. The model (OpenAI \texttt{gpt-5.6-luna}, reasoning effort low, at most 1,400 output tokens, prompt version \texttt{article\_casefit\_v1}) extracts the organism scope, the human clinical context (causal infection; colonization or contamination; reactivation or bystander; detection only; non-human; unclear), site and syndrome alignment, and four patient-specific dimensions (specimen, host, phenotype and temporal alignment), each rated match, partial, mismatch or unknown. A deterministic rule, not the model's own conclusion, derives the verdict: mismatch when the scope is not the exact species, the evidence is non-human, or the site or syndrome conflicts; insufficient when the hard gates (exact species, causal infection, and at least partial site and syndrome alignment) are not all met; strong match when site and syndrome match, at least one patient-specific dimension matches and none conflicts; and partial match otherwise. Colonization at a compatible site counts as counter-evidence. A traceability gate requires verbatim supporting and counter-evidence spans before an article enters aggregation. The numbers of strong and partial matches per candidate are the A1 signals used by \rfive. When frozen articles were missing for a candidate, the batch fell back to live PubMed retrieval; \todo{15} of \todo{62} case-fit artifacts record such a fallback, and the reported decisions replay from the frozen artifacts.

\subsection*{Sequencing strength, direct evidence and colonization gate (modules B, C and D)}
% RAG_re_clinical/rag_re_clinical/clinical_rules.py: evaluate_b_strict:805, grade_direct_evidence:944, specimen_colonization_gate:689, evaluate_temporal_coherence:1136; config/clinical_v1.json
Module B evaluates \mngs strength on two axes from the frozen candidate features. The absolute axis is positive when the signal tier is M1--M2 or the read tier is R3--R4; the relative axis is positive when dominance is D2--D3 or the priority is 1 with read percentile $\ge 0.8$. Site alignment is taken from structured candidate-specific evidence when present and from the upstream alignment label otherwise; an explicit site mismatch cannot be overridden by the generic label. \rfive requires either axis together with site alignment; the stricter conjunction of both axes is computed and reported but not used as a gate. Module C grades same-organism evidence from non-\mngs tests, using only structured records with a usable specimen site and an exact organism match: C3 when a high-specificity assay (culture, a molecular test or \filmarray with an explicit organism) is positive in a sterile-site or tissue specimen; C2 when such an assay is positive at the target site; C1 when only context is available (a positive record without a usable site, a record flagged as contaminated, a modality-level support summary, or respiratory \textit{Candida} supported only by culture); CNEG when an exact-organism structured test at the target site is explicitly negative; and C0 when no direct evidence exists, which includes pending, ordered and not-performed tests. Module D checks site coherence and colonization guardrails and returns pass, guarded, block or unknown; it is reported with every decision but is not a gate in \rfive. A temporal-coherence module (three days before and after the anchor) is computed for research arms only. The clinical configuration is versioned (\texttt{clinical\_v1}) and marked exploratory; changing any threshold requires a new configuration version (Supplementary Table~4).

\subsection*{Final selection rule (\rfive)}
% OBER_patient_delivery/generate_r5_final_decisions.py: RULE_FORMULA:17-21, evaluate_r5:98-116, compose_decision:150
For every candidate carried into the evidence stage, \rfive computes
\begin{align*}
\text{selected} \;=\; \text{picked} \;\lor\; \text{C3} \;\lor\; \big[&(\text{A1}_{\text{strong}} \ge 2 \;\lor\; \text{A1}_{\text{strong}}+\text{A1}_{\text{partial}} \ge 7)\\
&\land\; \text{site aligned} \;\land\; (\text{B}_{\text{absolute}} \lor \text{B}_{\text{relative}})\big],
\end{align*}
where picked denotes an upstream pick and the remaining terms are the module outputs defined above (rule identifier \texttt{R5\_A1\_UNION\_AND\_B\_LOOSE}; thresholds in Supplementary Table~4). Upstream picks are selected unconditionally and keep their order; rescued organisms are appended in alphabetical order, which carries no clinical ranking. For every patient, the rule path of each selected organism (direct evidence or case-fit with site alignment and sequencing strength), the gate values, the disposition of every non-selected candidate, the source file hashes and a manifest are written, together with the statement that failing the rescue rule does not exclude infection. The earlier pruning arms (a stricter B, D as a gate) are retained as research comparisons and were not used for any reported list.

\subsection*{Rationale generation and delivery}
% mngs_candidate_evidence_pipeline_20260902/mngs_candidate_evidence_pipeline/{build_candidate_window_evidence.py, build_rationale_views.py, generate_llm_rationales.py (gpt-5.6-luna, low:96-97), audit_llm_rationale_batch.py}; examples/full_pipeline_config.template.json (candidate_window_days 2:36-37); OBER_patient_delivery/{prepare_r5_rationale_inputs.py, assemble_r5_rationales.py, export_delivery.mjs, audit_delivery.mjs}
After \rfive, the patient's structured record is cut to an evidence window of two calendar days on either side of the \mngs anchor for candidate-specific microbiology (\todo{confirm the window from the run manifest; two days is the template default}), with the full time course retained in a separate view, and a rationale is generated for each selected organism by a language model (OpenAI \texttt{gpt-5.6-luna}, reasoning effort low) from these views and the frozen decision. The generator is instructed that selection and ranking are fixed. Its output is audited for structure (one entry per selected organism, no organism outside the selection, all required fields present), and any failure blocks delivery. A first-pass rationale written against the upstream picks is audited and then superseded by a second pass aligned to the \rfive selection, so that no delivered explanation refers to a superseded list. Delivery exports a simple table (hospital, patient, selected pathogens and reasons) and a traceable JSON, Markdown and XLSX package in which every organism links to its rule path, module results, article identifiers and input hashes, followed by an automated delivery audit. Delivered outputs are labelled as research results pending clinical review.

\subsection*{Direct-prompting comparison}
% LLM_test/direct_raw_benchmark/{direct_raw_runner.py (DROP_KEYS:37-70), prompt_v1.txt, input_identity.py, freeze_input_mapping.py, astra_batch.py (model, reasoning medium, 4000 tokens:17,59), compare_identity_reruns.py:120, evaluate_direct_raw.py}
To test whether the pipeline's advantage derives from its structure rather than from the language models it contains, four frontier models were given, for each of the \todo{41} patients, a single request containing the nine standardized clinical sections and the raw \mngs list (organism, reads, control codes and specimen), after removal of direct identifiers and of every field that could carry an answer (reference labels, upstream picks, review tiers and rationales). The mapping from patient to payload was frozen and verified by identity checks. After a correction to that mapping, 22 responses per model (66 of the 123 responses of \gptsol, \gptluna and \gptterra) were regenerated from the corrected payloads and the remaining 57 were verified byte-identical to their originals, so that all 123 responses of the three earlier models and all 41 responses of \gptastra correspond to the corrected payloads. The prompt (Supplementary Note~2; written in Traditional Chinese by the study team) casts the model as an infectious-diseases reviewer, states that detection is not causation, lists the colonization, site, \textit{Candida}, environmental and reactivation cautions, allows zero or more pathogens, requires species-level names and demands a JSON object with predicted pathogens, supporting evidence, counter-evidence, excluded organisms and limitations. The models were OpenAI \texttt{gpt-5.6-sol}, \texttt{gpt-5.6-luna}, \texttt{gpt-5.6-terra} and \texttt{gpt-6-astra} (\todo{dates of access}), called through the Responses API with reasoning effort medium, a JSON schema and at most 4,000 output tokens, without tools, retrieval or conversation history; each model was run once per patient. Every response was stored with the prompt hash, model identifier, reasoning setting and payload hash, and validated against them before scoring.

\subsection*{Outcome measures and scoring}
% LLM_test/direct_raw_benchmark/evaluate_direct_raw.py: FROZEN_SYNONYMS:12-27, summarize:75-115, cohort caveat:120-135
The unit of evaluation was the (patient, organism) pair. Predicted and reference organism names were normalized (Unicode NFKC, case and whitespace) and mapped through a frozen synonym table (for example, CMV to human cytomegalovirus, PJP to \textit{P.~jirovecii} and CRKP to \textit{Klebsiella pneumoniae}) plus per-cohort aliases. Matching was at exact species level; genus-level relaxation was not applied, so a prediction of \textit{Candida} against a reference of \textit{Candida tropicalis} counts as one false positive and one false negative. The primary outcome measures were precision, recall and F1 micro-averaged over pairs. Secondary measures, computed by the same script, were the per-patient (macro-averaged) values, the proportions of patients with at least one reference organism identified, with all reference organisms identified and with an exact set match, and the number of patients for whom a method returned no organism (Supplementary Note~5). Because both evaluation cohorts were restricted to patients with at least one adjudicated pathogen, the reported precision does not capture false positives in patients without a pathogen.

\subsection*{Computational reproducibility}

The pipeline is orchestrated by a single entry point that validates the cohort manifests and per-stage inputs, runs the stage programs in a fixed order as subprocesses and records every command, working directory and output hash in a run manifest; the orchestrator contains no selection logic, and a plan mode lists all stages and inputs without side effects. Output directories are never overwritten. The code carries SHA-256 manifests of \todo{382} research source files and \todo{470} package files, and editing any listed file fails source verification. The offline test suite (\todo{319} Python and \todo{8} Node tests) runs under a site customization that disables network sockets and removes API keys from the environment, so no test depends on a paid model or on live PubMed. The \todo{55} reported \rfive decisions, the \todo{62} case-fit artifacts and the \todo{164} direct-prompting outputs were replayed from their frozen inputs and reproduced the delivered files or metrics exactly; the v19 scorer used for the reported runs was recovered and verified against all \todo{55} saved scorer outputs. The reported runs used Python 3.13 and Node 24 on Windows (\todo{OpenAI SDK version; hardware}); macOS and Linux are untested.

\subsection*{Statistics and reproducibility}
No statistical method was used to predetermine sample size; the cohorts comprise every registry patient who met the inclusion criteria when the cohort manifests were frozen, and the small number of eligible patients is a limitation (Discussion). Patients were not randomized, because every method was applied to the same patients. Blinding was not applicable to the deterministic stages, which are exact functions of their inputs; the language-model stages received no reference labels, and predictions of every method were frozen before the reference labels were read by the evaluation scripts. The investigators who wrote the scoring rules and guardrails were not blinded to the reference labels: the rules were developed by iterating on the same cases with the labels visible, and no patient was held out from rule development, so the reported performance is a development-set result (Discussion) \todo{confirm that no case was held out}. Patients were excluded only for missing inputs, before any model was queried (Supplementary Fig.~1); no patient or prediction was excluded afterwards. The clinical records have never been made public, so the evaluation cohort cannot have been part of the training data of the language models. Precision, recall and F1 are point estimates from single runs: the deterministic stages replay identically, whereas the language-model stages were run once per patient (formatter, agents and safety review at temperature 1; article, case-fit and rationale generation at reasoning effort low; direct prompting at reasoning effort medium) and their outputs frozen, so run-to-run variability of these stages is not captured by the reported numbers. \todo{Add before submission: 95\% confidence intervals for every precision, recall and F1 by patient-level bootstrap (2,000 resamples of patients with replacement, pairs pooled within each resample); paired bootstrap differences in F1 between \toolname and each comparator on the same patients; an exact McNemar test on per-pair correctness where the pair sets coincide; and, if the budget allows, two further direct-prompting runs per model to report the run-to-run range. Report $n$ as patients and as pairs in every legend.}
